pawpages_credit_ledger

Every movement of a handler's credits: a daily refill in, a chat turn's charge out. The balance is the sum of credits; nothing stores it.

RLS  on, read only Primary key  id New for  v2

Columns

ColumnTypeNotes
iduuidgen_random_uuid()
handler_iduuid required → pawpages_handlers.id, on delete cascade.
kindtext required refill or turn. purchase joins them once credits are sold.
creditsinteger required ≥ 0 on a refill, ≤ 0 on a turn. 1 credit = $0.0001 of OpenAI cost, times CREDIT_MARKUP.
refill_datedate Refill rows only. The Asia/Kolkata day the refill is for.
conversation_iduuid Turn rows only. → pawpages_conversations.id, on delete set null.
cost_usdnumeric(12,8) Turn rows only, required there. What the turn cost at OpenAI, before markup.
input_tokens, cached_tokens, output_tokensinteger Turn rows only. Summed over every model call in the turn.
created_attimestamptzdefault now()
Why a ledger, not a balance column A balance column says how much is left but not why. Rows say both, and a purchase later is one more kind, not a new mechanism.
Why set null, not cascade, on conversation_id Cascade would delete a conversation's charges with it and hand the credits back.
Why cost and tokens are kept beside credits credits is what the handler paid, after markup and rounding up. The raw cost is what it cost us, so margins can be checked later without the per-machine usage log.
Why a refill row is written even when it adds 0 The row marks the day as refilled, so the refill doesn't try again on every request.

Functions

FunctionDoes
pawpages_refill_credits() Tops the caller up to 100 once per IST day, returns the balance. Called by GET /me and before every chat turn — there is no scheduled job.
pawpages_charge_turn(conversation, credits, cost, tokens…) Writes a turn's charge for the caller, returns the balance. Refuses a conversation that isn't the caller's, and a negative amount (the turn-shape check).
Why the balance may go below 0 A turn's cost is only known once it has run. The chat endpoint refuses a turn at ≤ 0 and charges afterwards, so the last turn of the day can overdraw by one turn's cost.

Indexes

IndexFor
pawpages_credit_ledger_one_refill_idx unique (handler_id, refill_date) — one refill per day, two tabs at once included. Turn rows have a null date, and nulls never collide.
pawpages_credit_ledger_handler_idx (handler_id) — the balance sum.

Row level security

PolicyRule
pawpages_handler_reads_own_credits select only. using: handler_id = (select auth.uid()).
Why no write policy Any insert policy would let a handler grant themselves credits. Both writes go through the two security definer functions above, which only ever top up to 100 or deduct. Never service_role.
