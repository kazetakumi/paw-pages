pawpages_entries

One row per logged event. One universal shape for a rabies booster, a vet visit and a nail trim — no per-type columns.

Why due_closed_at exists

Entry titles are free text, so the database cannot tell that "Rabies booster" and "rabies" are the same series. Nothing can close a due date automatically — somebody has to say so. That is what this column records, and it is the entire reason the pet page has a Mark done button.

Overdue is therefore always: due_on < current_date and due_closed_at is null.

Why weight lives here, not in its own table A weight is a thing that happened on a day — which is what an entry already is. Most readings are taken at a vet visit, so they belong to that row rather than a table joined back in. It earns real columns (not note) because it's the one field here a machine reads: comparing readings over time needs a number, not prose.

Constraints worth knowing

NameRule
pawpages_due_after_it_happened A next-due date cannot precede the date the thing happened.
pawpages_cannot_close_a_due_date_that_does_not_exist due_closed_at requires a due_on.
pawpages_weight_is_complete v1.1 Both weight_value and weight_unit, or neither. A number with no unit is not a weight.

Indexes

IndexServes
pawpages_entries_pet_feed_idx A pet's feed, newest first. (pet_id, happened_on desc, id desc) — the id breaks ties so pagination is stable.
pawpages_entries_open_due_idx The dashboard ledger. (pet_id, due_on) where due_on is not null and due_closed_at is null — only entries that still owe something.

Row level security

pawpages_handler_owns_entries all where the parent pet's handler_id equals (select auth.uid()), same on using and with check.

What's derived from this table

pawpages_due_items — one definition of "overdue"

A security_invoker view, so a handler reading it sees only their own pets automatically. Written once here rather than in every screen that needs it:

select e.id as entry_id, p.id as pet_id, p.handler_id, p.name as pet_name,
       e.title, e.due_on,
       e.due_on - current_date as days_until,
       e.due_on < current_date as is_overdue
from pawpages_entries e join pawpages_pets p on p.id = e.pet_id
where e.due_on is not null
  and e.due_closed_at is null
  and p.archived_at is null;

pawpages_public_entries — the gate for visitors

A visitor never has any policy on this table at all. They read this security definer view instead, which exposes title, happened_on and due_on — note, vet, due_closed_at and every row id are absent from the query, not filtered out. Two columns, added in 0007, are the one exception: photo_id and photo_path appear only when the handler set photo_is_public on that row — otherwise both are null, so an entry's id stays withheld unless its photo is already world-readable.
