Database

Paw Pages is moving to a chat-first frontend. This is where the v2 schema gets designed before any of it is migrated — one table at a time, settled here first. Nothing on this page is live.

Branch  v2.0.0 Project  kaze-master-in (oomzhjujlztfazvvsfrf) Live schema  verified directly against kaze-master-in, table by table, below New migrations  none written yet

Carried over from v1

Not up for re-litigation unless the chat-first rework actually forces it. Kept as-is, verified against the live tables rather than the (stale) v1 doc.

Handler owns pets, pet owns entries, one universal entry shape, dates are calendar dates never timestamps, due/overdue computed in a view, public page exposes a narrow column set through security definer views, RLS is the only access boundary — see CONTEXT.md for the full rule list. What v2 adds on top: the conversation itself is a table (pawpages_conversations, with its turns in pawpages_messages), and a chat-attached photo has a staging table of its own (pawpages_uploads) before it ever becomes a pet's or an entry's photo. How a free-text chat turn like "Biscuit had his deworming today, next dose in 3 months" gets parsed into an actual pawpages_entries row is app logic, not a schema question — nothing here needs to change to support it.

Tables

Filled in as we agree on each one. A row with no link hasn't been discussed yet.

TableStatusWhat it's for
pawpages_handlers settled One row per signed-up person. Kept from v1, unchanged.
pawpages_pets settled One row per animal. Kept from v1; gains an optional conversation_id in v2.
pawpages_entries settled One row per logged event. Kept from v1; widened by v1.1 with weight and an entry photo; gains an optional conversation_id in v2.
pawpages_conversations settled New for v2. One row per chat thread — title, which pets came up, when it was last active.
pawpages_messages settled New for v2 (0010, 0011). One row per item in a conversation — messages, tool calls and tool outputs — in order.
pawpages_uploads settled New for v2. Tracks a photo from the moment it's uploaded — in chat or from a pet's edit screen — until it's claimed as a pet's or an entry's photo.

Working method

We pick a table, argue about its columns and constraints until they hold up, then it gets its own page here and a row above turns from not started to settled. No SQL gets written until a table is settled.
