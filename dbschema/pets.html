pawpages_pets

One row per animal. Belongs to exactly one handler, carries its own public-page toggle, and can be archived without losing its history.

Constraints worth knowing

NameRule
pawpages_archive_is_complete Both archived_at and archived_reason, or neither. There is no such thing as a pet archived for no reason.
pawpages_dob_approx_needs_a_date dob_is_approx cannot be true with no date. "Approximately nothing" is not a state.

Indexes

IndexServes

Row level security

PolicyRule
pawpages_handler_owns_pets all where handler_id = (select auth.uid()), same on using and with check.

What a visitor sees

Anonymous visitors never touch this table. They read pawpages_public_pets, a security definer view scoped to where is_public and archived_at is null, exposing a fixed, coarser column set: slug, name, species, breed, colour, sex, photo_path, plus born (Mon YYYY) and precomputed age_years / age_months. The exact date_of_birth never leaves the table, and handler_id is absent entirely rather than filtered.

Why not RLS alone RLS decides which rows a visitor can read. It cannot hide columns. The public page problem is entirely about columns, so the view — not a policy on this table — is the gate.
